# DailyForge — deploy day runbook

Everything in this file is a click or a paste. It assumes nothing is set up yet, and it
is ordered so each step only needs things the previous steps produced.

Target, as chosen: **Neon** (free Postgres) + **Render** (free API) + **Netlify** (free
static host, installable PWA) + **Google sign-in**.

Budget once through: about 45 minutes, most of it waiting for the first builds.

---

## Before you start

Have open: GitHub (this repo), and a browser you are signed into Google with.

Two facts worth knowing before they surprise you:

- **The API sleeps.** Render's free tier stops the container after ~15 minutes of no
  traffic, and the next request takes 30–60 seconds to wake it. The app now says
  "Waking the server" instead of appearing to hang, and `.github/workflows/keep-warm.yml`
  keeps it awake during waking hours once you set one variable (step 6).
- **The hourly rollover job** (streaks, penalties, missed days) does not run while the
  instance is asleep. It is written to catch up whatever it missed on the next run, so
  an overnight sleep makes it late, never wrong.

## 1. Database — Neon

1. <https://neon.tech> → sign in with GitHub → **New project**.
2. Name `dailyforge`. Region: **AWS ap-southeast-1 (Singapore)** — closest to IST, and
   it must match Render's region or every query pays a round trip across the world.
3. Postgres version: the default is fine.
4. On the project dashboard, open **Connection Details** and switch the snippet type to
   **Java**. Copy the values out of it — you need three, separately:

   | What Render calls it | Where it comes from |
   |---|---|
   | `DATABASE_URL` | `jdbc:postgresql://<host>/<db>?sslmode=require` |
   | `DATABASE_USERNAME` | the user, usually `neondb_owner` |
   | `DATABASE_PASSWORD` | the password |

   **Use the pooled host** — the one whose name contains `-pooler`. The direct host
   allows very few connections on the free tier and Hikari will exhaust it.

   > Keep `?sslmode=require`. Neon refuses plaintext connections, and the failure looks
   > like a generic timeout rather than anything about TLS.

Nothing else to do here. Flyway creates every table on the API's first boot.

---

## 2. API — Render

1. <https://render.com> → sign in with GitHub → **New** → **Blueprint**.
2. Pick this repository. Render reads `render.yaml` and proposes a service called
   `dailyforge-api` — free plan, Singapore, Docker, health check on `/actuator/health`.
3. It will ask for the values marked `sync: false`. Fill in:
   - `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD` — from step 1.
   - `CORS_ALLOWED_ORIGINS` — you do not have the Netlify URL yet. Put
     `http://localhost:4200` for now and correct it in step 5.
   - `GOOGLE_CLIENT_ID` — leave **blank** for now; step 4 produces it.
   - `DAILYFORGE_AUTH_JWT_SECRET` is generated by Render. Do not set it by hand and do
     not copy one from anywhere else.
4. **Apply**. The first build takes 5–10 minutes (it is compiling the whole backend).
5. When it is live, note the URL: `https://dailyforge-api.onrender.com` (or whatever
   suffix Render gave it). Check it:

   ```
   https://<your-api>.onrender.com/actuator/health   →  {"status":"UP"}
   ```

   If it says `DOWN` or the deploy failed, open **Logs**. The two failures worth
   recognising:
   - `FlywayException` / `relation already exists` → the database is not empty. On a
     fresh Neon project it should be; if you re-ran something, drop the schema in Neon's
     SQL editor (`DROP SCHEMA public CASCADE; CREATE SCHEMA public;`) and redeploy.
   - `Connection refused` / timeouts → wrong host, or you used the non-pooled one.

## 3. Frontend — Netlify

1. <https://netlify.com> → **Add new site** → **Import an existing project** → GitHub →
   this repo.
2. Netlify reads `netlify.toml` from the repository root, so leave the build settings
   alone. It will
   show base `frontend`, command `npm run build:deploy`, publish `dist/frontend/browser`.
3. Before the first deploy, add the environment variable (**Site configuration** →
   **Environment variables**):

   | Key | Value |
   |---|---|
   | `API_BASE_URL` | `https://<your-api>.onrender.com/api/v1` |

   This is baked into the bundle at build time by `frontend/scripts/set-api-url.mjs`.
   Changing backends later is a change to this variable and a redeploy — never a commit.

4. Deploy. Note the site URL, e.g. `https://dailyforge.netlify.app`.
   Rename it under **Site configuration → Site details → Change site name** if you want
   something nicer; do it now, before it is in the OAuth config.

---

## 4. Google sign-in

1. <https://console.cloud.google.com> → **New Project** → `DailyForge`.
2. **APIs & Services → OAuth consent screen**:
   - User type **External**, then **Create**.
   - App name `DailyForge`, your email for both support and developer contact. Save.
   - **Audience → Test users → Add users**: add your own Google address. Leave the app
     in **Testing**. Publishing is only needed when someone other than your test users
     signs in, and publishing invites a verification review you do not want today.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - Application type **Web application**, name `DailyForge web`.
   - **Authorised JavaScript origins** — add both, exactly, with no trailing slash:
     - `http://localhost:4200`
     - `https://<your-site>.netlify.app`
   - **Authorised redirect URIs**: none needed. The frontend gets an ID token from
     Google in the browser and posts it to the API, which verifies the signature,
     `aud`, `iss` and expiry server-side before issuing DailyForge's own session. A
     Google token is never accepted as a session token.
   - Create, and copy the **Client ID** (it ends in `.apps.googleusercontent.com`).
4. Back in **Render → dailyforge-api → Environment**: set `GOOGLE_CLIENT_ID` to that
   value and save. Render redeploys. The Google button appears on its own — the
   frontend asks the API which sign-in methods exist and hides what is switched off.

---

## 5. Close the loop on CORS

Now that the Netlify URL exists, go back to **Render → Environment** and set:

```
CORS_ALLOWED_ORIGINS = https://<your-site>.netlify.app
```

Exactly the origin, no trailing slash, no wildcard, and no `localhost` in the list.
Save; Render redeploys.

Optionally tighten the CSP: in `netlify.toml` (repository root), replace
`https://*.onrender.com` in `connect-src` with your exact API origin, then push.

---

## 6. Keep it awake

**GitHub → repo → Settings → Secrets and variables → Actions → Variables → New variable**:

| Name | Value |
|---|---|
| `API_HEALTH_URL` | `https://<your-api>.onrender.com/actuator/health` |

`.github/workflows/keep-warm.yml` pings it every 12 minutes between 06:30 and 00:30 IST.
Until this variable exists the workflow does nothing rather than failing noisily.

---

## 7. Install it on your phone

1. Open the Netlify URL in **Chrome on Android**.
2. Either take Chrome's own install prompt, or open the app's **Settings → This app →
   Install app**.
3. It lands on your home screen with the DailyForge icon and opens without browser
   chrome.

There is nothing to reinstall later. Every deploy reaches the installed app on its own:
the service worker notices the new build, and the app offers **Reload**.

---

## 8. Prove it works, in this order

1. Sign up with email and password. The header score shows 0.
2. Create a habit, tick it. The score moves, and the toast offers Undo.
3. Sign in with Google in a private window. It should link to the same account if the
   email matches, not create a second one.
4. **The multi-device check, which is the whole point:**
   - Open the app on your desktop and your phone, both on the Rewards page.
   - On the phone, edit a reward's cost. Save.
   - On the desktop — without reloading — edit the same reward and save.
   - The desktop must refuse with *"That was changed on another device. Showing you the
     latest."* and then show the phone's value. It must **not** silently overwrite it.
   - Switch away from the desktop tab and back: it re-reads on its own.
5. Check `Settings → This app` shows a version matching the commit you deployed.

## Deploying a change, from here on

```
git push origin main
```

That is the whole procedure. CI runs the backend suite, the frontend suite, and applies
the migrations to a real Postgres; only if all of that is green do Render and Netlify
build. An installed phone picks the new frontend up on next launch and offers Reload.

**When the change includes a migration**, do this first, once:

1. Neon → **Branches** → create a branch from `main` (this is a full copy-on-write copy,
   free, and instant).
2. Point a local run at the branch and apply the migration there before it goes near the
   real data:
   ```
   docker run --rm -v "$PWD/backend/src/main/resources/db/migration:/flyway/sql:ro" \
     redgate/flyway:11 -url="jdbc:postgresql://<branch-host>/<db>?sslmode=require" \
     -user=<user> -password=<password> migrate info
   ```
3. If it applies cleanly, push. Delete the branch afterwards.

## When something is wrong

| Symptom | Look here first |
|---|---|
| App loads, every request fails | CORS. The origin in Render must match the site exactly. Check the browser console for the blocked-origin message. |
| First open of the day takes ~a minute | Expected on the free tier. Check `API_HEALTH_URL` is set (step 6). |
| Google button missing | `GOOGLE_CLIENT_ID` unset or the Render redeploy has not finished. |
| Google button errors | The site origin is not in **Authorised JavaScript origins**, or you added a trailing slash. |
| "That was changed on another device" when only one device is open | A second tab is open somewhere. That is the feature working. |
| Phone shows an old version | Open it, wait for the Reload prompt, or close it from recents and reopen. |
| Score looks wrong | The ledger is the truth. `POST /api/v1/points/recalculate` rebuilds the cache from it; the rebuilt total must equal `SUM(amount)`. |

**Backups.** Neon's free tier keeps a 24-hour history and can restore to any point in
it. Before any migration that touches `points_entry`, make a Neon branch first — that
is your backup, and it costs nothing.
